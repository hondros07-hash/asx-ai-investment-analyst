# AXÍA V23.12 — Performance validation

This release hardens the existing short-lived per-session company navigation cache.
It does not claim a measured production speedup.

## Expected behavior

- Reopening a research subpage for the same exact ticker and period within 45 seconds reuses the session snapshot.
- `ZIP` and `ZIP.AX`, or `1y` and `5y`, never share snapshots.
- Caller mutations cannot alter cached financial bars or provider metadata.
- Empty provider history clears the prior snapshot and does not fetch a profile.
- An explicit refresh bypasses the session snapshot. Streamlit provider caches remain authoritative; this does not bypass their own TTL.
- Market ribbon remains an independently refreshing Streamlit fragment. No live quote TTL is increased.

## Verify before merge

Run `python -m unittest tests.test_navigation_performance_v2312` and the existing test suite. Compare navigation timings in `st.session_state["_axia_navigation_timing_v23723"]` on Overview → Fundamentals → Technical, same ticker and different ticker, both warm and cold. Check that provider errors do not display a previous company's data. Compare mobile and desktop layouts. This PR does not alter the UI, fundamentals formulas or SEO.

## Future performance work

Measure cold-start, provider latency, cache hit rates and p95 route timings in a staging environment before changing additional TTLs or adding concurrency. Shared Redis caching belongs to the FastAPI deployment, not this Streamlit session cache.
