# V23.4.5 deployment

1. Back up Supabase and apply `supabase/migrations/20260925_v23_4_5_trial_eligibility.sql` before deploying this app. It replaces the older automatic trial grant triggers. Existing trial windows are preserved.
2. Configure `CHRIMATA_TRIAL_HMAC_SECRET` with a stable randomly generated secret of at least 32 characters on the server, alongside the existing Supabase server keys. Never put these in the frontend.
3. Deploy the backend and Streamlit app together. The existing Streamlit registration now records a server-side attempt and activates eligible trials on verified sign-in. The FastAPI registration accepts an optional 64-character hexadecimal `device_signal`; no browser fingerprinting script is bundled or automatically collected.
4. Call authenticated `POST /api/v1/me/activate-trial` after email verification for the Next.js client. It is idempotent. Review outcomes remain Free until a separately designed manual verification flow exists.
5. Test new registration, confirmation, repeated activation, and no-config fail-closed behavior in staging. A migration alone does not validate a live Supabase deployment.

Limitations: New emails without a verified shared identity can still receive another trial. A browser-supplied device signal is spoofable and is only a review signal. Stripe verified payment identity, durable rate limiting, a review workflow, and privacy/retention controls are future work. No claim of complete duplicate-person prevention is made.
