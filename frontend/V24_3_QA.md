# AXÍA V24.3 — Stage 4 integration and QA gates

This release adds executable CI checks and hardens server API boundaries. **It is not a certification of feature parity, security, or production readiness.**

## Automated gates
- Backend mocked integration tests for route registration, invalid tickers, empty provider data, non-US filing boundaries and workspace screening.
- Existing Stage 2/3 and navigation cache regression tests.
- Frontend TypeScript and Next.js production build.
- Server API requests have a 12-second client timeout; invalid API paths/payloads return explicit errors. Empty financial snapshots are not cached.

## Manual staging acceptance (record pass/fail and evidence)
1. Home → Search → each of eleven Command Centre sections → Markets → Screening → Research Tools; test back/forward and deep links.
2. Compare ZIP.AX, KO and QAN.AX against Streamlit and official issuer filings. Check exchange, reporting currency, periods, source timestamps, financial ratios and missing-value handling.
3. Test mobile 375px, tablet 768px and desktop 1440px for navigation, chart/table overflow, keyboard focus and screen-reader labels.
4. Force API 503/504, disconnected backend, empty data and invalid ticker; verify no stale company data, fabricated prices or hidden errors.
5. Inspect server logs for sensitive data and verify no client-side API secrets, wildcard CORS or public personal-data endpoints.
6. Verify robots, sitemap, canonical URLs and noindex for company and personal workspace routes on staging.
7. Benchmark cold/warm navigation and provider timeouts. Record actual p50/p95 and provider cache hit rates before setting targets.

## Release blockers
- Authenticated per-user Watchlist, Portfolio, Alerts and saved thesis/catalyst data are not migrated.
- Official non-US disclosure connectors and full AI report analysis are not migrated.
- Comprehensive screening, consolidated calendar and full Streamlit feature parity are not established.
- CI execution and manual staging sign-off are required; no production cutover or automatic deployment in this PR.

Rollback: leave the current Streamlit deployment and domain unchanged. Deploy Next.js to a separate staging origin; reverse staging release if acceptance fails.
